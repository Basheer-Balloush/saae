- Feedback survey: questions live only in src/lib/feedback-survey.ts; public writes go through server functions (honeypot + IP rate limit), reads/updates only by `admin` role via RLS — keeps contact data out of public queries.
- Course feedback (LMS, after lessons + quiz, before the certificate) is separate from that survey: forms live in the database (`lms_feedback_forms` + frozen `lms_feedback_form_versions`, edited by LMS admins; `DEFAULT_FORM` in src/lib/course-feedback-survey.ts only seeds the default). All writes go through server functions; learners read their own response, LMS admins read everything, instructors nothing.
- Coupons and course payments (migrations 20260929150000/150100/170000): every rule is enforced in SQL (`lms_coupon_quote`, `lms_submit_enrollment_request`, `lms_record_payment`, …); src/lib/coupons.ts only mirrors the price math for display. Percentage discounts may have an optional whole-pound minimum and an optional maximum, and never exceed the course price. One coupon per learner per course ever; recognition codes mark a course completed (`lms_enrollments.completion_source = 'recognition'`) and skip lessons/quiz but not feedback. Recognition requires a code, once per learner, subject to the code's total use limit. An existing enrollment can redeem a code without changing its balance; cancelling that redemption is blocked to protect the existing enrollment. Payment entries are insert-only; corrections are opposite entries. Learners never read `lms_coupons`; instructors see neither coupons nor payments. PGlite tests for these rules live outside the repo (ask for the harness).
- Guests (migration 20260929160000) are Supabase anonymous users (`auth.users.is_anonymous`, `useLmsAuth().isGuest`). They request courses and learn like anyone; `lms_block_guest_rows` triggers refuse them coupons, certificates, reviews and trainer/intern applications, and `lms_evaluate_certificate` answers `account_required`. Creating an account converts the guest in place (`lms_finish_guest_upgrade`, after the emailed link in `lms_guest_upgrades`); signing in to an existing account merges the guest into it (`lms_merge_guest`). Idle guests are deleted nightly by pg_cron (`lms_cleanup_idle_guests`). "Allow anonymous sign-ins" in Supabase Auth must stay on for the guest button to work.
